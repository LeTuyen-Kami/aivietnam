<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser client -> broadcaster APIs | Untrusted caller may attempt direct token/start/end calls |
| Middleware edge -> route handlers | Middleware UX checks can be bypassed without server enforcement |
| Next route handlers -> Payload Local API | Risk of privilege escalation if Local API runs with default override |
| Next route handlers -> Stream server SDK | Token and call-control operations must stay server-side with secret protection |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | E | `src/app/(frontend)/api/stream/broadcaster-token/route.ts` | mitigate | Enforce `payload.auth({ headers })` + `isUsersCollectionAdmin` before token minting, return 401/403 on failure, never expose Stream secret/client token generation to browser. |
| T-04-02 | S/E | `src/app/(frontend)/api/livestreams/[id]/start/route.ts` and `/end/route.ts` | mitigate | Re-authorize on server for every request; never trust middleware/session hints alone; require admin and verify target livestream exists before mutation. |
| T-04-03 | E | Payload Local API updates in start/end handlers | mitigate | When acting on behalf of authenticated user, always pass `overrideAccess: false` to prevent Local API access-control bypass. |
| T-04-04 | T | Livestream lifecycle transitions | mitigate | Only set `status=live` after successful ensure/join orchestration and set `status=ended` only on explicit end endpoint request. |
| T-04-05 | I | Broadcaster token handling | mitigate | Use short-lived server-generated tokens and dedicated admin-only token route separate from member token route (D-10, D-09). |
</threat_model>
