|----------|-------------|
| Browser broadcaster UI -> admin APIs | Untrusted frontend must not gain publish capabilities without server authorization |
| SSR page guard -> client component | Client UI must not be treated as authz control plane |
| Payload admin links -> frontend broadcaster route | Deep links must not imply permission without middleware/server checks |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-06 | E | `src/app/(frontend)/broadcaster/[slug]/page.tsx` | mitigate | Enforce server-side authz guard (`payload.auth` + `isUsersCollectionAdmin`) and render 403 for non-admin even if client-side routing is manipulated. |
| T-04-07 | S/T | `src/app/(frontend)/broadcaster/[slug]/Broadcaster.client.tsx` | mitigate | Fetch tokens only from admin-only endpoint; do not embed static tokens or secrets; route start/end through server handlers to prevent client-forged state transitions. |
| T-04-08 | I | Broadcaster token lifecycle | mitigate | Use `tokenProvider` short-lived token fetches and avoid long-lived token persistence to local storage/session storage. |
| T-04-09 | E | Payload lifecycle mutation path | mitigate | Depend on Plan 04-01 guarantees: start/end handlers must update documents with `overrideAccess: false` when user context is present to prevent Local API bypass. |
</threat_model>
