## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label micro gaps, compact status chips |
| sm | 8px | Button internal spacing, small stacked text gaps |
| md | 16px | Default card/body spacing and paragraph rhythm |
| lg | 24px | Section spacing inside viewer containers |
| xl | 32px | Separation between major viewer sections |
| 2xl | 48px | State placeholder vertical breathing room |
| 3xl | 64px | Page-level top/bottom spacing for standalone live page |

Exceptions: none. Minimum tap target remains 44px height for interactive controls where applicable (default applied for accessibility).

## Phase-Specific Interaction Contract

- Route contract: viewer page is `\`/live/[slug]\`` and requires authenticated member session (source: D-01, D-06).
- Auth failure contract: unauthenticated access redirects to home with `auth=login_required` and `returnTo` for same viewer URL (source: D-01).
- Join gating: only attempt Stream join when session status is `live`; never join for `draft`, `scheduled`, or `ended` (source: D-09).
- Data authority: server fetch for livestream-by-slug must use Payload Local API with `user` + `overrideAccess: false` (source: D-03).
- Token behavior: viewer uses Stream `tokenProvider` calling `POST /api/stream/token`; on `401`, route through login and return to same URL (source: D-02, D-05, D-07).
- Status transition UX: while open, viewer polls status and auto-switches placeholder to player when `scheduled -> live`; switches to ended state when `live -> ended` (source: D-12).
- Lifecycle hygiene: create Stream client/call only for live state and always clean up on unmount or status change (source: D-11).
- Connection resiliency: rely on Stream SDK auto-reconnect and show lightweight reconnecting feedback during transient disconnects (source: D-10).
